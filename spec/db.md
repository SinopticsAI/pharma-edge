# База кабинета: PostgreSQL

Система записи кабинета живёт в управляемом кластере `orders-panel-pg`
(`c9qbferg3hcqjnqkghcp`, PostgreSQL 16), база **`pharma_cabinet`**.

Ростер пайплайна остаётся в YDB на стороне Plane (`plane_cases`,
`plane_case_items`, `plane_agent_reports`) — это изолированное эфемерное
состояние, которое ни с чем не соединяется джойнами.

Канон DDL — [`sql/01_cabinet.sql`](../sql/01_cabinet.sql). Применяется
скриптом [`infra/scripts/apply-sql.ps1`](../infra/scripts/apply-sql.ps1).

## Почему не YDB

Прежняя схема не использовала ничего YDB-специфичного: список кейсов читался
как `SELECT * FROM cases LIMIT 200` и сортировался в Python, фильтра по
арендатору не было. Модель после сверки с MedMost стала жёстко реляционной —
аккаунт → компании → продукты → кейсы → документы, слоты, варианты, узлы, — а
агрегаты «N действий ждёт вас» и «следующее действие по каждому продукту» в
SQL считаются одним запросом.

Плюс JSON: раньше он лежал строками в `Utf8`, теперь это `jsonb` с индексами,
и провенанс поля вида `draft->>'legalName'` стал запрашиваемым. Память Mastra
всё равно требует PostgreSQL — адаптера YDB у него нет.

## Подключение

| Параметр | Значение |
| --- | --- |
| Хост | `c-c9qbferg3hcqjnqkghcp.rw.mdb.yandexcloud.net` |
| Порт | **6432** — пулер Odyssey в режиме транзакций |
| Базы | `pharma_cabinet` (Edge), `pharma_agent` (Mastra) |
| TLS | `sslmode=verify-full`, корневой сертификат Яндекса |
| Сеть | функции и контейнер поднимаются с `--network-id` сети кластера |

Порт именно 6432. На 5432 сессионный пул, и серверлес-вызов его исчерпает.

Лимиты: на `b1.medium` потолок 200 соединений минус 15 служебных, по умолчанию
50 на пользователя. Соединение в функции создаётся вне обработчика и
переиспользуется между вызовами; приостановленный инстанс теряет сокет,
поэтому [`edge_pg.py`](../scr/_shared/edge_pg.py) один раз переподключается,
а не роняет запрос.

## Инварианты

Часть держится базой, часть — функциями. То, что можно выразить ограничением,
выражено ограничением: проверка в коде забывается при следующей правке.

- `products_approval_order_check`: клиент не может утвердить раньше специалиста.
- `classification_variants_forbidden_check`: вариант `forbidden` нельзя выбрать.
- `organization_items_product_check`: документ уровня product обязан знать свой продукт.
- Кейс не переходит к подаче без завершённого мандата и закрытого списка моделей.
- Трек фиксируется после квалификации.
- `status_proposals` не становится фактом без подтверждения оператора с артефактом.
- Каждый запрос фильтруется по `account_id` из проверенных claims.

## Аренда

Изоляция арендаторов — не свойство схемы, а дисциплина запросов: `account_id`
есть в каждой таблице и обязан быть в каждом `WHERE`. Строковая политика
безопасности не включена, потому что подключение общее для всех аккаунтов;
если это изменится, RLS станет следующим шагом.
